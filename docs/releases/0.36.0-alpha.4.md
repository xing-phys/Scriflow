Scriflow **0.36.0-alpha.4** (versionCode **86**) adds automatically configured model profiles.

## What changed

- **Fetch → select → Add:** enter the provider, endpoint and API key, tap **Fetch available models**, check the models you want and **Add selected**. Their available limits, image support and thinking options are saved automatically. Select one in Model ID and **Save AI settings**. Up to 64 models are kept per endpoint; **Manage saved models** removes unchecked profiles without deleting chats.
- **Automatic configuration:** context/input limits and output maximums appear with the source and check date. Thinking defaults to **Automatic (provider default)**. Optional effort choices contain only advertised values, and the app uses each provider's matching request fields. There is no need to enter model specifications manually.
- **Choose in chat:** tap the provider/model name in the header to choose a saved model for a new chat and make it the default. The previous session and draft are saved first. Dragging the title still moves the window; History still reopens or deletes earlier sessions.
- **Respect model limits:** reply budgets are capped by reported limits; known non-chat or image-incompatible requests are rejected locally. A conservative text estimate guards known input/context limits without silently discarding history. Rejected drafts stay editable and can be shortened and resent.

## Metadata and privacy

Claude and DeepSeek expose native capability metadata. Google's standard endpoint uses its native model API for limits while chat continues through the existing interface. OpenAI's standard model list lacks detailed specifications, so fetching the current model or adding selected models can read their public official documentation from `developers.openai.com`. Those documentation requests never carry the API key, conversation or notebook content. Other metadata requests authenticate only with the configured provider. No third-party model registry is used.

Custom servers use their own metadata; unfamiliar or unavailable specifications remain marked as provider defaults. Saved profiles work offline. They contain public configuration and optional effort preferences, with API keys encrypted separately. Profiles and chat histories are outside notebook backups. Choosing or adding a model never sends a chat automatically.

## Verification

**272,886 JVM assertions in 97 suites and fourteen real-browser cases pass**, plus Android debug/release lint/build checks and permanent-signer verification. New fixtures cover native metadata and pagination, public documentation and snapshot IDs, no credentials in documentation requests, saved model preferences, provider-specific thinking parameters, output limits and editable context rejection. Automated tests make no live provider calls.

No tablet is connected. Physical Settings/model-picker layout, native input and live provider-account acceptance remain pending. Exact image/token accounting is provider-dependent; the local text guard deliberately uses a conservative estimate.
