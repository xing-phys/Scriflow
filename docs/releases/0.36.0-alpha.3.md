Scriflow **0.36.0-alpha.3** (versionCode **85**) adds saved AI chat sessions.

## What changed

- **A new chat by default:** opening AI chat from the toolbox starts a fresh session. Conversations and unsent text/image drafts save automatically. **+** starts another while keeping the previous chat. Untouched empty sessions do not fill history.
- **Find and reopen chats:** tap the history list icon in the chat header. Sessions appear newest first with automatic titles, provider/model, dates, message counts and draft indicators. Tap a row to restore its conversation, attachments and draft; follow-ups include only that session's messages.
- **Delete sessions:** tap a row's trash icon and confirm. Deletion removes that session's local history and draft. Other sessions are unaffected, and pending replies or stale windows cannot recreate it.
- **Keep the original destination:** reopened chats retain their provider, endpoint and model. They remain readable without a key; configure the original endpoint and its key in Settings before sending. Rotation and temporary app suspension retain the active session when Settings have not changed.
- **Keep earlier chats:** existing version-1/2 conversations, including images and drafts, import automatically. If an older file's provider/model cannot be identified, opening it asks before assigning the current configuration. Reopening never sends automatically.

## Storage and privacy

Sessions are local private files, shared across notebooks and excluded from editable notebook backups. API keys remain encrypted separately using Android Keystore and are never stored in session archives. History listing, reopening and deletion make no provider request. Deletion does not remove provider-side records. Send shares only the chosen session's submitted messages and attachments with its configured provider.

Each session keeps the existing text/image limits. New session archives contain metadata and the existing version-2 conversation snapshot; older AI APKs cannot read them. **Notebook/backup format 8 is unchanged.**

## Verification

**272,815 JVM assertions in 96 suites and fourteen real-browser cases pass**, together with Android debug/release lint/build checks and permanent-signer verification. History fixtures cover independent sessions, draft/image recovery, metadata-only listing, original provider/model matching, migrations, failed atomic saves, deletion retries and late-response rejection. Window fixtures cover New chat, Activity retention and native input barriers while history is visible.

Physical MatePad Paper acceptance and live calls using the owner's provider accounts remain pending. No paid provider calls were made during automated validation.
