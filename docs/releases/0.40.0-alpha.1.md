# Scriflow 0.40.0-alpha.1

The bookshelf now opens a web browser directly and includes a permanent
**Saved websites** folder for local, offline page copies.

- **Browser** uses the device's Chromium-based Android WebView, with an HTTPS
  address bar, Back/Forward, Reload and pinch zoom.
- **Save** captures the current loaded page, including captured text, images,
  styling and frame contents. Each save is an independent snapshot with its
  title, original address, save time and size.
- Open a snapshot from **Saved websites**, even after restarting Scriflow with
  Wi-Fi off. Offline reading blocks scripts and network loads. External links
  offer a separate online opening, and snapshots can be deleted after confirmation.
- Complete archive/metadata pairs publish together. Failed or interrupted saves
  stay out of the folder, and storage work stays off the handwriting writer.

Each save covers one page. Scroll to load wanted images before saving; linked
pages need their own saves. Forms, streamed media and other interactive services
may require the original online page. This first version supports HTTPS websites;
HTTP, file downloads and multiple tabs are not supported. Snapshots are private
local files outside notebook backups and are removed by clearing app storage
or uninstalling.

The APK is versionCode **101** and uses the permanent release signing certificate.
Notebook and chat formats are unchanged from 0.39. Install as an in-place update
without uninstalling. See [Browser and offline websites](../browser.md).

Validation passes the host suites with 276,708 reported assertions, including
92 real-file website storage/address assertions, plus the real Chromium archive
round trip through production storage and a fresh offline browser (10 checks),
the existing Markdown/PDF/AI regressions, Android debug/release lint/builds and
permanent signer verification. **No tablet was connected.** Browser rendering and navigation,
page saving/reopening after a restart with Wi-Fi off, touch/zoom, portrait/landscape
layout and e-ink refresh still require testing on the target device.
