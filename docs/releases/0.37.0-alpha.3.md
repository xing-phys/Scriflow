Scriflow **0.37.0-alpha.3** (versionCode **91**) reduces automatic display work
between handwritten strokes.

## Changes

- Protect a complete writing burst, including pending native completions and a
  300 ms quiet interval after the latest pen contact. Keep repeated display
  notifications as one latest update per component.
- Hold automatic Undo/Redo/menu changes and completed-ink paper redraws while
  writing. Keep Huawei's native live ink and immediate background stroke saving.
- Freeze the Zen seconds clock during writing, then catch up. AI requests and
  saves continue, while conversation formatting, render polling and automatic
  chat scrolling wait. Long writing does not consume the renderer's timeout.
- Defer passive floating-note PDF/image/metadata refreshes and tool-hint expiry.
  Keep explicit reader gestures, editing/navigation and lifecycle cleanup.

The native handwriting adapter, pressure renderer, append/saving implementation
and display policy are unchanged. Existing safe native repair may still run
after the writing burst when controls expose ink. See the
[design and validation limits](../handwriting-priority.md).

## Verification and update

**276,325 JVM assertions in 114 suites and fourteen browser cases pass**,
alongside Android debug/release lint/build checks and permanent-signer
verification. The checks exercise rapid strokes, delayed native commits,
immediate save dispatch, pending-save preview, UI/JavaScript races, timeout
accounting and retired owners alongside existing storage/rendering regressions.
**Physical stylus latency, e-ink refresh and handwriting acceptance remain
pending.** This release does not claim that the reported intermittent issue
was reproduced or eliminated on the tablet.
